# ModelJetty 产品决策

## 服务谁、解决什么问题

首要用户调整为需要连接模型的小团队与个人应用开发者。使用者消费 HTTPS 网站、API 与 App；Kubernetes 学习与实验属于维护者路径。第一批协作者仍应能在没有云账号、没有模型 API Key 的情况下参与。见 [产品定位](POSITIONING.md)。

使用者的核心任务：连接一个自己的实例，发出请求，在网站与移动端确认处理结果并恢复故障。维护者另行完成部署、多副本与运维实验。每轮围绕这两条路径分别验收。

## 当前迭代：v0.1.1，首次使用与跨端联动

根据 v0.1 的代码审查确定以下问题，而非已经完成用户访谈：

| 优先级 | 观察到的问题 | 交付与验收 |
| --- | --- | --- |
| P0 | 网站/App 必须手动刷新，难以感知联动 | 连接后前台每 5 秒同步状态；可关闭，后台与断开后暂停；不轮询模型接口 |
| P0 | 失败只显示状态码或 JSON 解析异常 | 认证、限流、Redis、上游、网络问题给出下一步操作；HTML 错误页保留原 HTTP 错误语义 |
| P0 | 限流后容易反复点击或误以为系统会重试 | 根据 Retry-After 禁用发送并倒计时；到期恢复按钮，绝不自动重发 POST |
| P1 | 没有明确的第一次使用路径 | 网站展示连接→发送→多端记录三步；Flutter 空状态说明步骤 |
| P1 | 请求看不出来自哪里，失败难以关联 | 显示网站/App/API 来源；成功与失败有请求 ID，网页可展开完整 ID，App 可选择复制详情 |
| P1 | 同步失败时旧统计看起来仍是当前状态 | 保留最近成功同步时间，显示“上次数据”，恢复后清除同步失败提示 |

同步是基于轮询的最终一致性，正常网络下约一个刷新周期可见。不是 WebSocket 推送或 5 秒 SLA。来源由端点和客户端声明推断，仅用于展示，不是可信审计凭据。历史记录没有来源字段时显示“未标记”。

## 每轮的产品验证

网站首页首先解释“面向谁、解决什么问题、怎样体验”。默认只突出免费模拟体验及其结果；管理令牌、统计表格和自托管说明通过折叠区域按需展开。产品差异化表达聚焦统一入口、请求追踪与可操作的恢复提示，不宣称全球首创或尚未完成的智能诊断。视觉使用系统字体、充足留白和单一主要操作，避免把控制台字段当作新用户首页。

1. 首次连接：用户能知道令牌在哪里、该输入哪一种令牌。
2. 首个请求：用户能确认当前是模拟模型还是真实付费上游，能看到回复与请求 ID。
3. 跨端联动：另一个客户端请求后，无需手动刷新即可看到记录和来源。
4. 故障恢复：消息文本保留；显示恢复提示；失败后不产生隐式模型重试。
5. 移动与后台：390px 无页面横向溢出，后台不持续轮询，重连不显示旧实例回复。

自动化覆盖上述关键行为；不把自动化代替真实用户反馈。下一步请一位新贡献者从干净环境按 README 启动，记录卡住的位置和耗时，再调整入门路径。暂不采集用户行为数据。

## 下一轮优先级

1. **可访问的预览**：先在已有 EC2 上完成域名、HTTPS、真实浏览器调用、跨端记录及重启恢复，提供可复现的维护步骤。当前是可信测试者共用的单租户实例。
2. **降低首次体验门槛**：设计与管理台隔离的免费模拟演示，让访客无需索取管理令牌也能体验；明确共享数据边界、限制请求并禁止接入付费上游。完成隔离验证后才开放匿名调用。
3. **贡献者与客户端验证**：让一位新贡献者从干净环境完成入门；在具备 macOS 条件时验证 iOS 编译与真机 HTTPS。
4. **K8s 复现**：先在免费的本地 kind 集群完成双副本、滚动更新和恢复实验。云端迁移需要另行批准资源，不在现有 1 GB 实例上强行安装。

## 成本约束

不订阅付费服务，不新增计费资源，不升级现有 EC2，不启用付费模型 API。使用免费开源依赖、临时域名和模拟模型。已有 EC2 的计算、存储与网络仍按 AWS 现有规则计费；“没有新增订阅”不等于服务器完全免费。

SSE、更多供应商、Keychain、多租户和计费保留在长期路线图；当核心路径可复现后，再根据实际需求排期。每个增量应带验证记录和一个可审查的 Git 提交。
