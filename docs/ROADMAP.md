# 发展目标

定位：个人开发者的单租户 AI Gateway，用于自托管与 Kubernetes 学习。HTML 网站负责桌面管理，iOS App 负责移动查看与试验。

不以 star 数为验收标准。每个阶段需要可复现的行为、测试和文档，以每次 20–40 分钟的小任务推进。

## v0.1：可演示的闭环

- 无云账号模拟模型，HTML 与 Flutter 发送请求、查看相同记录。
- 多网关实例通过 Redis 共享缓存、配额和统计。
- 管理和调用凭证隔离，不记录 prompt 或上游密钥。
- WSL 与 Compose 说明，K8s 多副本与 HPA 配置，测试与贡献指南。
- 分别报告平台验证，不把 web 编译当作 iOS 真机验证，不把 YAML 校验当作集群运行。

## v0.2：可运维的本地集群

v0.1.1 已优先改善首次使用与联动：前台自动同步、后台暂停、请求来源与完整 ID、错误恢复提示和限流倒计时。产品取舍与验收标准见 [PRODUCT.md](PRODUCT.md)。

1. 在 kind 部署，记录版本、命令和双副本验证结果。
2. 规范镜像 tag，加入手动触发的 GHCR 发布和最小 workflow 权限。
3. 集成测试覆盖 Redis 故障、滚动更新、Pod 重建后的状态。
4. Prometheus/Grafana 示例，区分全局业务指标和单 Pod 指标。
5. 使用合理负载验证 HPA，说明 CPU 对 I/O 网关的局限。

## v0.3：iOS 与上游体验

1. 在 macOS/Xcode 和 iPhone 验证链路、网络失败与可访问性。
2. Keychain 存储可撤销凭证，替代当前会话内存方式。
3. SSE、取消、超时与背压，先测试再开放。
4. 受控重试、模型路由、按上游的错误统计。

## v0.4：面向外部用户

1. 可撤销、有权限范围的客户端密钥。
2. 先定义和测试租户隔离，再做多租户配额、审计、计费；不能沿用当前全局 Redis key。
3. TLS、Redis ACL/TLS、备份恢复、依赖漏洞检查和发布说明。
4. 根据真实用户反馈决定是否提供托管服务，不提前承诺收入。
